## 1. 项目简介与产品定位

**The Liar（骗子酒馆）** 是一款基于浏览器、零后端依赖的社交推理卡牌游戏。每局随机从 Q / K / A 中抽取一张作为「目标牌」，玩家轮流出牌并**宣称**自己打出的都是目标牌（牌背朝上，他人无法验证真伪）；下一位玩家可以选择**相信**或**质疑**。质疑后亮牌：若出牌者说谎则出牌者受罚（开枪），若质疑错误则质疑者受罚。枪为 6 发，前 5 发各 50% 概率击发、第 6 发必死——存活到最后者获胜。

**产品定位**

- **娱乐向社交推理小游戏**：把「骗子酒馆」的核心张力（表演、诈唬、读心）浓缩进一局几分钟的对局。
- **LLM 角色扮演演示载体**：通过给每个 AI 玩家配置不同性格与独立 API，把「大模型对话」变成可见、可玩的实时表现，而非只回答问题。
- **零部署门槛的纯前端 Demo**：单 HTML 文件、无构建、无服务器，双击即玩，也方便二次开发与教学演示。

**核心特点**

- 发牌左→右逐张铺开、护盾/开枪动画、华丽胜者结算界面等完整视听反馈。
- 手牌区双侧对称信息面板（左侧本局揭穿统计、右侧对手剩余牌数）。
- 内置启发式 AI 负责**决策**（出几张、是否质疑）；LLM 负责**发言**（性格化台词），二者解耦。
- 严格的**信息隔离**：提示词只暴露玩家自己的手牌与公开信息，AI 看不到他人底牌。
- 未配置 API 或调用失败时自动回退到内置语料，保证永远能玩。

## 3. 启动方式与环境变量说明

### 3.1 三种启动方式

**方式 A：直接打开（最省事）**
- 双击 `index.html`（或 `TheLiar_standalone.html`）即可在浏览器中游玩。
- 适用于纯单机 / 内置 AI 模式。但浏览器在 `file://` 协议下调用外部 LLM API 可能遭遇跨域拦截（见 3.4）。

**方式 B：本地静态服务器（推荐用于接入 LLM）**
```bash
# 进入项目目录后，任选其一启动一个静态服务器
python -m http.server 8000
# 或
npx serve .
```
然后浏览器访问 `http://localhost:8000`。`http(s)` 协议下大模型接口调用更顺畅。

**方式 C：在线访问**
- 直接打开第 2 节给出的部署地址即可，无需任何本地环境。

### 3.2 环境要求

- 任意现代浏览器（Chrome / Edge / Firefox / Safari，建议近 3 个版本）。
- 若需接入 LLM：一个 OpenAI 兼容的 API 地址、模型名与 Key（如 DeepSeek、OpenAI、智谱、Google 等）。
- 无需 Node.js / 无需数据库 / 无需编译构建。

### 3.3 配置项说明（"环境变量"对应关系）

> 本项目是**纯客户端应用**，没有后端进程，因此**不存在操作系统级的环境变量（env）**。所有可配置项均在应用内通过「AI 设置」面板完成，并持久化到浏览器的 `localStorage`（存储键：`theLiarAiConfig`）。下表等价于传统项目的"配置/环境变量"清单：

| 配置项 | 作用域 | 说明 | 默认值 / 示例 |
| --- | --- | --- | --- |
| **API 地址** | 全局 | OpenAI 兼容的 Chat Completions 完整端点 | `https://api.deepseek.com/v1/chat/completions` |
| **模型名称** | 全局 | 调用的模型 ID | 推荐 `deepseek-v4-flash`（亦可用 `gpt-4o`、`glm-4-flash` 等） |
| **API Key** | 全局 | 鉴权令牌，请求时以 `Authorization: Bearer <key>` 发送 | `sk-...` |
| **玩家姓名** | 单个 AI | 该 AI 在游戏中的显示名 | 如「老千」「戏精」 |
| **性格 / 人设** | 单个 AI | 写入系统提示词，决定发言风格（拱火/冷静/狡猾…） | 自由文本 |
| **使用独立 API** | 单个 AI | 勾选后可为该 AI 单独指定 API 地址/模型/Key | 关闭（默认复用全局） |

配置入口：游戏内右上角 **「AI 设置」** 按钮 → 填写全局三项 + 各 AI 玩家卡片 → 点「保存」。保存后即时生效并持久化。

### 3.4 关于浏览器跨域（CORS）的说明

大模型接口通常要求请求方携带 `Origin`。在 `file://` 协议下浏览器发出的 `Origin` 为 `null`，部分厂商（含 OpenAI、DeepSeek 等）可能拒绝此类跨域请求。解决方案：
1. 用方式 B（本地 `http` 服务器）或方式 C（已部署的 `https` 站点）打开；
2. 或在 API 侧开启 CORS / 使用本地代理转发。

## 4. 核心使用流程与 AI 介入环节说明

### 4.1 核心游戏流程

1. **开局**：随机选定本轮目标牌（Q / K / A 之一），每位玩家发到等量手牌。
2. **轮流出牌**：当前玩家从手牌中选择若干张，牌背朝上打出，并**宣称**这些都是目标牌（可真可假）。
3. **质疑或相信**：下一位玩家决定——相信则自己成为新的出牌者；质疑则进入结算。
4. **结算亮牌**：翻开刚打出的牌。
   - 若并非全为目标牌 → **出牌者说谎**，出牌者开枪受罚（前 5 发 50% 概率、第 6 发必死）。
   - 若全为目标牌 → **质疑错误**，质疑者开枪受罚。
5. **淘汰与胜负**：受罚致死的玩家出局；存活到最后一人者获胜，触发华丽胜者结算。

### 4.2 AI 介入环节（关键）

本项目的 AI 分两层，**决策与发言解耦**：

- **决策层（内置启发式，不依赖 LLM）**
  - 由 `aiTurn` / `aiChallengeDecision` 等函数用规则与随机性决定：出几张牌、是否质疑。
  - 即使完全不配置任何 API，游戏也能正常进行（内置 AI 自动对局）。

- **发言层（LLM 生成，可配置）**
  - 触发点 `triggerBanter(actor, count)`：每当有玩家出牌后，**其他存活的 AI 玩家各自通过 LLM 生成 1–5 句短评**，错峰以气泡显示。
  - 单句生成函数 `getAIBubble(player, situation, extra)`，按场景 `banter / play / challenge / pass` 拼装提示词。
  - **信息隔离**：系统提示词明确约束——AI **只能知道自己的手牌与公开信息**（目标牌、轮次、存活者），**禁止**透露或推断他人底牌，从机制上保证公平与"诈唬感"。
  - **兜底机制**：若未配置 API、请求超时（9 秒 `AbortController`）或返回异常，自动回退到内置 `DIALOGUE_POOL` 语料，保证发言环节不中断。

- **LLM 调用实现**
  - `callAI(player, systemPrompt, userPrompt)`：向 OpenAI 兼容端点 `POST` 请求，携带 `model` 与 `messages`，`temperature=0.9`、`max_tokens=240`。
  - 优先使用玩家**独立 API**，否则使用全局 API；失败/超时/未配置返回 `null`。

### 4.3 如何接入你自己的大模型

1. 打开游戏 → 右上角「AI 设置」。
2. 全局项填：API 地址（完整 `/chat/completions` 端点）、模型名称、API Key。
   - 例（DeepSeek）：地址 `https://api.deepseek.com/v1/chat/completions`，模型 `deepseek-v4-flash`。
3. （可选）为每个 AI 玩家单独设定姓名、性格人设，或勾选「使用独立 API」隔离其模型。
4. 点「保存」，再点「测试连接」验证；看到 `✅ 连接成功` 即生效，之后每轮出牌都会看到 AI 的性格化发言。

## 5. 技术栈清单

| 分类 | 技术 | 说明 |
| --- | --- | --- |
| 语言 | HTML5 / CSS3 / JavaScript (ES6+) | 单文件、零框架 |
| 渲染 | 原生 DOM + 内联 SVG（base64 data URI） | 所有图标/插画内联，无外链资源 |
| 样式 | 纯 CSS（关键帧动画、Flex/Grid 布局） | 发牌铺开、弹窗缩放、胜者流光等均 CSS 实现 |
| 存储 | Web Storage API（`localStorage`） | 持久化 AI 配置（键 `theLiarAiConfig`） |
| 网络 | Fetch API + `AbortController` | 调用 OpenAI 兼容 LLM 接口，9s 超时 |
| 通信协议 | OpenAI Chat Completions 兼容格式 | 支持 DeepSeek / OpenAI / 智谱 / Gemini 等 |
| 构建/依赖 | **无构建步骤、无第三方依赖、无后端** | 双击即玩，部署即静态托管 |
| 部署 | GitHub Pages（`gh-pages` 分支，单文件静态托管） |

**为什么没有后端？** 游戏状态完全在浏览器内维护，LLM 由前端直接调用（用户自带 Key）；配置与对局数据均留在本地，既零成本又保护密钥不外泄。

## 6. 常见问题 / 故障排查

- **连接失败：`HTTP 400 ... but you passed gpt-4`**
  模型名称填错了。默认已预填为 DeepSeek 的 `deepseek-v4-flash`；若你改用其他厂商，请把「模型名称」改成该厂商的真实模型 ID，例如 OpenAI 用 `gpt-4o`、智谱用 `glm-4-flash`。

- **连接失败：网络/跨域(CORS)错误**
  多为 `file://` 协议导致。改用本地 `http` 服务器（方式 B）或已部署的 `https` 站点（方式 C）打开即可。

- **AI 不说话 / 只说内置台词**
  未配置 API 或调用失败，已自动回退内置语料。检查「AI 设置」中的地址/模型/Key，并用「测试连接」验证。

- **想换模型但不想改代码**
  直接在「AI 设置」里改模型名称与地址即可，无需触碰源码。
